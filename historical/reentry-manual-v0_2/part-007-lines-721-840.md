# 11. How to handle a new discovery service

A discovery service (Epstein discovery, extremism discovery, mailbox discovery, public-record crawler, specialist archive, etc.) should be treated as a **sensor**, not a truth authority.

Preferred output packet:

```text
lead identifier
source URL / archive pointer / stable record ID
discovery method
first-seen/access time
source identity
document/item identity
bounded claim candidates
possible duplicates / lineage parents
known revisions/corrections
possible specialist routes
uncertainty / missingness
why the lead matters
```

Then Intake decides whether it becomes a source item, claim, event update, route, or rejection/defer record.

Discovery multiplicity is not evidence multiplicity.

# 13. Common failure modes and repairs

## Failure: “I did not see it, therefore the project lacks it.”
**Repair:** search current names, aliases, old names, distributed forms, historical paths, and commit history before reconstruction.

## Failure: creating a new event for every new article.
**Repair:** determine whether this is a world-state change, evidence-state change, projection/rhetoric change, or correction.

## Failure: repeated reporting counted as corroboration.
**Repair:** trace underlying evidence lineage. Syndication and mailbox delivery are discovery paths, not independent sources.

## Failure: source/institution grades itself.
**Repair:** official statement proves the institution made the statement. It does not independently adjudicate contested truth.

## Failure: repository name becomes verdict.
**Repair:** `Real-Bad-Policy`, `Proven-Harm`, `Extremism-Watch`, `Geopolitics`, and `Capital-and-Power` are jurisdictions/work surfaces, not automatic classifications.
