# 1. Ninety-second fresh-chat re-entry

If you have almost no context, do this in order:

1. Read this file.
2. Open `UNUM-Lattice-News/README.md`.
3. Open `UNUM-Lattice-News-Intake/README.md`.
4. Read `UNUM-Lattice-News/registries/REPOSITORY_CUSTODY.yaml` if repository ownership is unclear.
5. Read `UNUM-Lattice-News-Intake/sources/README.md` and `sources/REGISTRY.yaml` before creating a new source identity.
6. If the question is cross-border/state/bloc/war/occupation/sanctions/security related, open `UNUM-Lattice-News-Geopolitics/README.md`.
7. If the question is money/ownership/labor/debt/trade/procurement/campaign-finance/material-flow related, open `UNUM-Lattice-News-Capital-and-Power/README.md`.
8. Check current high-centrality ledgers listed in Section 10 below.
9. Search existing files before creating a new study, claim, event, source, or route.
10. For new public-reality discovery, land it in **Intake first** unless it is clearly a reviewed update to an already durable Lattice object.
11. Route specialist questions; do not let routing create corroboration or silently transfer evidence custody.
12. Return earned specialist findings to Intake/Main with the original evidence lineage intact.

Tiny recovery lock:

```text
find the existing seat
-> recover the evidence lineage
-> identify the exact claim/edge being updated
-> route only what belongs elsewhere
-> return the earned result
-> preserve the way back
```


The mesh may contain overlapping identities, flows, constraints, harms, gains, narratives, ownership paths, institutional crossings, and correction routes.

Core traversal:

```text
enter anywhere

-> follow materially relevant relations
-> trace power / value / harm through transformations

-> test redress / resistance / feedback
-> project a dated account
```
