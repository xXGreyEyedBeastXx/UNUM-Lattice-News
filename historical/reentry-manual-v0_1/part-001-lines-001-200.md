# 1. Ninety-second fresh-chat re-entry

If you have almost no context, do this in order:

1. Read this file.
2. Open `UNUM-Lattice-News/README.md`.
3. Open `UNUM-Lattice-News-Intake/README.md`.
4. Read `UNUM-Lattice-News/registries/REPOSITORY_CUSTODY.yaml` if repository ownership is unclear.
5. Read `UNUM-Lattice-News-Intake/sources/README.md` and `sources/REGISTRY.yaml` before creating a new source identity.
6. Check current high-centrality ledgers listed in Section 10 below.
7. Search existing files before creating a new study, claim, event, source, or route.
8. For new public-reality discovery, land it in **Intake first** unless it is clearly a reviewed update to an already durable Lattice object.
9. Route specialist questions; do not let routing create corroboration or silently transfer evidence custody.
10. Return earned specialist findings to Intake/Main with the original evidence lineage intact.

Tiny recovery lock:

```text
find the existing seat
-> recover the evidence lineage
-> identify the exact claim/edge being updated
-> route only what belongs elsewhere
-> return the earned result
-> preserve the way back
```

# 2. The five Lattice News repositories

## A. `xXGreyEyedBeastXx/UNUM-Lattice-News`

**Role:** durable public reality mesh and cross-domain reconstruction surface.

Owns:
- reviewed events and chronology;
- durable claims and source lineage;
- state transitions;
- cross-domain causal relations;
- uncertainty and corrections;
- accountability and power relations;
- historical lineage studies;
- dated public-facing analysis after review.

Key distinction:

```text
lattice = durable storage/index/record surface
mesh = living causal topology being investigated
```

The mesh may contain overlapping identities, flows, constraints, harms, gains, narratives, ownership paths, institutional crossings, and correction routes.

Do not treat a node, legal entity, jurisdiction, accounting category, organization name, or repository label as a causal wall.

Core traversal:

```text
enter anywhere
-> resolve identity / kinship / lineage
-> follow materially relevant relations
-> trace power / value / harm through transformations
-> preserve uncertainty on weak edges
-> test redress / resistance / feedback
-> project a dated account
```

## B. `xXGreyEyedBeastXx/UNUM-Lattice-News-Intake`

**Role:** preferred upstream discovery, source custody, verification, claim extraction, evidence typing, chronology separation, and routing seat.

Intake exists so gathering can be broad without making the durable Lattice noisy or falsely certain.

Preferred lifecycle:

```text
external public reality
-> discovery
-> source verification
-> duplicate / citation-lineage review
-> bounded claim extraction
-> clock separation
-> world-state vs evidence-state triage
-> evidence-jurisdiction typing
-> competing-model / discriminator review
-> proposed routing
-> human/reviewer check
-> reviewed crossing packet
-> UNUM-Lattice-News
```

**Intake has no publication authority.** Entry into Intake does not manufacture guilt, harm, motive, ideology, causal role, extremism, legality, or moral verdict.

Promotion states currently include:

```text
INTAKE_CANDIDATE
SOURCE_REVIEWED
CLAIM_TESTED
STATE_TRANSITION_REVIEWED
ROUTING_REVIEWED
READY_FOR_LATTICE_REVIEW
REJECTED
DEFERRED
```

Promotion is claim-specific. Different edges from the same article may occupy different states.

## C. `xXGreyEyedBeastXx/UNUM-Lattice-News-Proven-Harm`

**Role:** downstream high-confidence harm ledger.

This repository records harm relations that have **already earned** a high-confidence state. It does not make harm true by naming it.

Use when the packet can preserve:
- actor/institution;
- affected party/population;
- exact harm;
- exact causal relation;
- time window and scope;
- best available evidence;
- independent corroboration where warranted;
- adjudicated findings where relevant;
- typed evidence effects;
- remaining uncertainty/missingness;
- explicit proof state;
- correction/demotion path.

Useful proof states include:

```text
DIRECTLY_DOCUMENTED
ADJUDICATED_OR_OFFICIALLY_ESTABLISHED_WITH_SCOPE
STRONGLY_CORROBORATED
CAUSAL_RELATION_HIGH_CONFIDENCE
HARM_ESTABLISHED_CAUSE_PARTIAL
HARM_ESTABLISHED_ATTRIBUTION_DISPUTED
```

Never turn a whole historical lineage into one undifferentiated harm claim. Promote exact harm edges only.
